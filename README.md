# RAG over arXiv Graph Neural Networks for Drug Discovery Papers

Retrieval-Augmented Generation system built over a corpus of arXiv papers on
graph neural networks (GNNs) applied to drug discovery: molecular property
prediction, virtual screening, drug-drug interaction prediction, and molecule
generation. Two retrievers (BM25 and dense embeddings) are compared, feeding
into the same LLM generation pipeline (Groq, Llama 3.3 70B).

Course project — see `report/report.docx` for the full write-up.

## Setup

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

Create a `.env` file in the repo root with a free Groq API key ([console.groq.com](https://console.groq.com)):

```
GROQ_API_KEY=your_key_here
```

## Reproducing results

```bash
python run_all.py
```

This runs, in order: preprocessing/chunking, the corpus-suitability diagnostic
(10 questions, no retrieval), and the full retrieval + generation evaluation
on the gold question set for both BM25 and dense retrieval. All outputs land
in `eval/results/`.

One step in the pipeline is inherently manual, per the assignment spec: generation
answers are graded by a human (correct / cited / appropriate "I don't know"), not
by an automatic metric. The first time you run `run_all.py`, it will generate
`eval/results/human_grading_template.csv` and stop before the final summary step.
Copy that file to `eval/results/human_grading.csv`, fill in the `_yn` columns by
hand, then re-run `run_all.py` (or just `python src/eval/summarize_human_grades.py`)
to produce `eval/results/generation_summary.json`. Re-running `run_all.py` after
that point will not overwrite your filled-in `human_grading.csv`.

Random seeds are fixed throughout (`config.SEED = 42`): used for embedding/model
determinism and passed as the `seed` parameter on every Groq API call.

To re-collect the corpus from the arXiv API instead of using the committed
snapshot in `data/raw/papers.jsonl`, run `python src/collect_corpus.py` — this
is not part of `run_all.py`, since arXiv results can drift over time (new papers
matching the query) and would break reproducibility of the numbers reported.

## Repo structure

- `src/collect_corpus.py` — pulls the corpus from the arXiv API
- `src/preprocess.py` — cleaning, chunking, metadata assignment
- `src/retrieval/bm25.py` — classical BM25 retrieval
- `src/retrieval/dense.py` — sentence-transformer embedding retrieval
- `src/generation/` — prompt templates and LLM answer generation (Groq)
- `src/run_diagnostic.py` — corpus-suitability diagnostic (no-retrieval baseline)
- `src/eval/run_eval.py` — retrieval + generation evaluation on gold questions
- `src/eval/summarize_human_grades.py` — aggregates human-graded generation results
- `run_all.py` — single command that reproduces all results/tables
- `data/raw/papers.jsonl` — frozen corpus snapshot (360 papers)
- `data/processed/chunks.jsonl` — cleaned/chunked corpus (526 chunks)
- `eval/gold_questions.json` — hand-written gold evaluation set
- `eval/diagnostic_questions.json` — corpus-suitability diagnostic questions
- `eval/results/` — all evaluation output (generated by `run_all.py`)
- `report/` — project report
